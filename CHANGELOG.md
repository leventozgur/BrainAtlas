# Changelog

## Unreleased

- BA-68: `sync status` no longer reports `SYNCED` while the last completed run refused files (secret filter or denied path). It now reports `PENDING` with `refusedCount` and `refusedFiles` (path and rule id only, never content) until the offending files are fixed and a run succeeds.
- `safety.secretFilter` can now be set to `false` in the custom profile (it stays locked in Lite and Full, and switching an opted-out config to those profiles is refused with `E_LOCKED_KEY`). Off means writes are no longer refused for secret-like content: MCP page writes and crosslink titles, `checkpoint` with `secretFilter: false` and the `maintain --fix` index line skip `scanText`. Path deny rules, output redaction (hooks, recap, CLI, receipts) and the sync and synthesis scans are unchanged. `doctor` and `config set` warn while it is off. New core export `secretFilterEnabled(config)`.

- Fix two macOS-flaky tests and bound CI time: concurrent first use of the sync host identity no longer fails with `E_INVALID_PATH` while another process is publishing `host-id` (the temporary link is removed right after publishing and readers wait out the brief two-link state); the MCP semantic fallback test gives its fingerprint-mismatch server its own state so that server's background rebuild cannot replace the shared index; the CI test job times out at 30 min and each test at 5 min.

## 0.1.0-rc.13 — 2026-11-21

Per-agent channel and agent management, plus a fix for the dead semantic hook path in installed Full releases. The default install (MCP + hooks) is unchanged, and without a `channels` entry every file written is byte-identical to rc.12. Also ships the work merged since rc.12: `maintain --weekly` and synthesis review (BA-48), identifier and provenance retrieval fixes, and the corrected `status` semantic freshness count (BA-50).

- BA-61 (phase 3): adapter `detect(env)` (contract v2) is now evidence-based and returns `{detected, evidence}` from home directories and `PATH` commands (read-only, no absolute paths); `brainatlas agent list` shows `detected`/`evidence` and `init` without agents suggests `detectedAgents` (never installs automatically).

- BA-61 (phase 2): `brainatlas agent list | add | remove | set` adds, removes or switches the `mcp`/`cli` channel of one agent after installation without `uninstall` and without touching the other agents (`E_AGENT_SWITCH` when a switch fails and the previous channel is restored).

- BA-61 (phase 1): per-agent channel in configuration. `init --channel claude-code=cli,kiro=mcp` stores an optional `channels` map (the global `channel` stays the default for other agents), `effectiveChannel(config, agent)` is exported from core, `status` adds `agentChannels`, `config set/unset channels...` is rejected with `E_CHANNEL_SWITCH`, and without `channels` every written file is byte-identical to before.

- BA-59: the prompt hook and core vault templates now find the release root from an installed `node_modules/@brainatlas/<name>/` copy (new `packageRootFromUrl`), so an installed Full release no longer records `semantic: "fallback:module-missing"`.

- BA-58: documentation, test and consistency fixes for BA-48: the synthesis mode default is documented as `off` with `shadow` as the first review step, the `--weekly` wording matches the configured model step (the vault is still never written), `maintain --fix` skips an index line whose title or summary matches a safety rule and reports `secret-filter` with rule ids only, and the review tests cover `E_APPLY_VERIFY` and the retrieval rollback.

- BA-56: the current-state synthesis path (`maintain --weekly` with `maintain.synthesis.mode` `shadow`/`on` and `maintain --proposals accept`) now keeps restricted pages (`sensitivity: personal` / `inject: never`) away from the model, secret-scans the prompt and the model output and skips the page with `unsafe-input`/`unsafe-output` (rule ids only), writes proposal records and the ledger with mode `0600` inside `0700` directories, skips the model with reason `offline` when `BRAINATLAS_OFFLINE=1`, and refuses `maintain --proposals accept` outside the configured vault with `E_NOT_CONFIGURED_VAULT`. See `docs/user/maintain.md`.

- BA-57: an accepted `maintain --proposals` "current state" block is detected by its `<!-- brainatlas:current-state -->` marker and presented as synthesized: `synthesized: true` in `search`/`pageSections`, no `trust: 'verified'` on that result, `[synthesized]` in hook title and pointer lines, and the same field through MCP `wiki_query` (lexical and hybrid); ranking is unchanged.

- Documentation fixes: the comparison tables in both READMEs are replaced by a sourced related-work list, the READMEs carry the measured semantic numbers, the safety contract carries the measured BA-26 result, the hook deadline wording matches the code, vulnerability reporting is private, and the Turkish README gains a user-guides section.

- Fixed `brainatlas status`/`doctor` semantic index freshness being measured against the vault root instead of `wiki/` (stale was always 0 and missing counted every vault Markdown file).

- BA-54: `brainatlas maintain --repo DIR` now verifies the `@<commit>` suffix of `repo:` sources with read-only git and reports `unknown-commit`, `source-drift` (the file changed between the commit and `HEAD`; uncommitted changes are ignored) and `unverifiable` (no git, not a work tree, unresolved `HEAD`, shallow clone or timeout) as new finding kinds; they appear in the report, the human output and `--queue` but not in `counts`. See `docs/user/maintain.md`.

- BA-53: `retrieval.pullLowConfidence` now defaults to on, so below-threshold `wiki_query` results are returned flagged `lowConfidence` instead of an empty list, in MCP and `brainatlas wiki query`; an explicit `false` restores the old empty-on-abstain behaviour, and the hook path is unchanged.

- Added Prettier as a development-only formatter (`npm run format`, `npm run format:check`): the JavaScript sources are formatted once with the shared `.prettierrc.json`, CI runs `npm run format:check` after `npm run typecheck`, and the supply-chain guard allows the pinned dev-only root `prettier`; no formatting or behaviour change beyond whitespace, and no release archive changes.

- BA-48 phase B3: new `brainatlas maintain --proposals list|show <id>|accept <id>|reject <id> [--vault PATH] [--json]` reviews stored "current state" proposals. `show` prints the delta, block and a fresh unified diff; `accept` re-runs the gates under the Wiki write lock, applies the same `--keep 3` compaction, verifies both written files, restores them when a lint, OKF or retrieval check regresses, and records one content-free `synthesis-accept` log entry. See `docs/user/maintain.md`.

- BA-48 phase B2: `maintain --weekly` can generate "current state" proposals with an external model command under weekly call and USD caps, through `maintain.synthesis.mode` (default `off`; set `shadow` first to only store proposals for review). Proposals are stored under `<stateDir>/<vaultId>/synthesis/` for review only — the vault is never written, no background process is started, and a failing model step never fails the weekly run. See `docs/contracts/config.md` and `docs/user/maintain.md`.

- `brainatlas maintain --weekly`: one read-only weekly run that writes a content-free snapshot (report counts, fix plan counts, compaction candidates) to `<stateDir>/<vaultId>/maintenance/weekly-YYYY-MM-DD.json`, keeps the newest 12 snapshots and optionally queues review candidates; plain `maintain` prints one reminder line when the vault's last weekly run is more than 8 days old. BrainAtlas installs no OS scheduler; run `brainatlas maintain --weekly` from your own scheduler (launchd, a systemd user timer or cron) if you want it automated. The weekly run never writes the vault, and it calls no model unless `maintain.synthesis` is configured (see the BA-48 phase B2 bullet). See docs/user/maintain.md.

- `brainatlas maintain --fix (--plan | --apply) [--sources]`: a safe, mechanical repair mode on top of the read-only report. It appends one index line per unlisted page under the page folder's H2 section (or `## Unsorted (maintain --fix)`), rewrites a broken wikilink to plain text when exactly one vault-root `archive/` file matches, and with `--sources` lists existing, unlinked `sources` files under `## Source files`. `--plan` writes nothing; `--apply` runs under the Wiki write lock, proves line by line that no original line was lost (`E_FIX_VERIFY`), writes atomically, adds one content-free `wiki/log.md` entry per changed file and is idempotent. Everything else stays report-only in `unfixed`. On a 300-page vault `--plan` took about 1 s. See docs/user/maintain.md.

- Added TypeScript `checkJs` type checking without a build or emit: `npm run typecheck` runs `tsc -p tsconfig.json` over the product code, CI runs it after `npm run lint`, and the supply-chain guard allows the pinned dev-only roots `typescript` and `@types/node`; no runtime dependency and no release archive changes.
- Added ESLint (flat config) as a development-only tool: `npm run lint` is lint-clean, CI runs it after `npm run guard`, and the supply-chain guard allows the pinned dev-only roots `eslint`, `@eslint/js` and `globals`; no runtime dependency and no release archive changes.
- Added `npm run release:verify -- --dir <folder>` (`scripts/release-verify.mjs`) to check a built release folder's required files, checksums, allowed signers copy, signature, distribution contents and version, and to run a clean install with `brainatlas doctor`.
- Wall-clock latency tests (hook startup p95, session-start p95, warm query medians, scanner and CLI timing bounds) moved to `tests/perf/` and a new `npm run test:perf`; `npm test` no longer runs them, and a separate non-blocking `perf` CI job runs them so machine load cannot fail the main test job.
- `brainatlas config set` now writes optional keys that the config schema defines but the current file omits (for example `hooks.disclosure` and `retrieval.exclude`), and the new `brainatlas config unset KEY [--plan]` removes a known optional key; unknown, required and locked keys keep failing with `E_CONFIG_KEY`/`E_LOCKED_KEY`.

## 0.1.0-rc.12 — 2026-11-17

Shell access for machines that cannot register MCP servers or hooks. The default install (MCP + hooks) is unchanged.

- New read-only command group `brainatlas wiki query|read|index|list|status|lint [--vault PATH] [--json]`. Each subcommand calls the same MCP read tool in-process (no second copy of search or read logic); `--json` output is deep-equal to the registered MCP server's answer for the same tool and arguments, and tool errors keep their `E_*` codes. Changing the channel of an existing install requires `brainatlas uninstall` first (`E_CHANNEL_SWITCH`). In the cli channel there is no automatic context injection. Without `--channel` every file written by the five adapters is byte-identical to before. See docs/user/cli-channel.md.

## 0.1.0-rc.11 — 2026-11-16

Retrieval quality, safety and maintenance. Linked pages, provenance trust, identifier-aware search and current-state snippets improve which page and section reach the agent; new `maintain`, `compact` and `usage` commands help keep long-lived vaults healthy; MCP writes are locked and atomic. Progressive disclosure and semantic search in the prompt hook stay opt-in.

- Incremental retrieval index: after a page edit only that file's records are updated instead of rebuilding the whole keyword index (per-file records and delta postings in `retrieval-index.json`; global statistics recomputed). Measured on a synthetic 10,000-page vault: refresh after one edit p50 about 2.5 s → 0.27 s; results identical to a full rebuild on the evaluation sets; hook p95 on 2,000 pages unchanged. The cache format changes, so existing caches are rebuilt once.
- `brainatlas maintain --repo DIR`: also checks code references in OKF `sources` and `symbols:` against the working tree at `DIR` and reports `stale-source` / `stale-symbol`. Read-only: only files are read, no git command runs. On an independent test 28/28 broken references were found with 0/61 false positives; about 0.4 s on 2,000 pages. Without `--repo` the report is unchanged.
- Prompt hook scope: when the vault has a `wiki/` folder the hook searches only `wiki/` (as MCP already did); root navigation and policy pages (index, log, agent policy) and `planning/`, `archive/`, `inbox/`, `raw/` at the vault root no longer appear in injected results but still count in index statistics. New `retrieval.exclude` setting. On an independent holdout the share of such meta pages among injected results fell from 0.49 to 0, false injections from 0.34 to 0.25, with needed pages injected unchanged.
- Safer MCP writes: a vault-wide write lock and atomic temp-file-plus-rename writes. `wiki_read_page` returns the page `sha256`, and write tools accept an optional `expectedSha256` that fails with `E_CONFLICT` when the page changed in between; a busy lock fails with `E_BUSY` after 5 seconds. In separate-process race tests lost index lines fell from 29/100 to 0/100 and lost page updates from 50/50 to 0/50. Responses without `expectedSha256` are unchanged.
- Secret and personal-data protection: new secret rules (Azure storage keys and SAS, `Authorization: Bearer`, GitLab and Azure DevOps tokens, Turkish `şifre`/`parola` keys including URL parameters); Turkish ID numbers (checksum) and TR IBANs (mod-97) are personal findings (writes refused, output redacted); e-mail addresses and TR phone numbers are redacted in hook output; pages with `sensitivity: personal` or `inject: never` are never injected by the hook. Independent test: 96/96 captured, 0/450 false positives.
- A page with unparseable frontmatter is now skipped instead of making hook, MCP and CLI search fail for the whole vault; `maintain` reports it as `invalid-frontmatter`.
- MCP hybrid results (bug fixes): anchors match keyword results, snippets never split an astral character, and `score` is the active mode's ordering key (`semanticScore` and `rrfScore` are extra fields); result order is unchanged.
- New command `brainatlas compact --page wiki/<page>.md --plan|--apply [--keep N] [--older-than YYYY-MM-DD]`: moves the older dated `##` sections of a long page (headings containing a `YYYY-MM-DD` date; `Current`/`Güncel durum` sections never move; the newest 3 stay by default) byte for byte to `wiki/archive/<name>-history.md` (`status: archived`) and adds an `## Archived history` back-link. `--plan` writes nothing; `--apply` runs under the Wiki write lock, verifies that no line is lost before writing, adds one `wiki/log.md` entry and prints how to undo; a second run moves nothing. On a copy of a real vault it shrank 8 of 9 oversized pages with no lost line. No LLM, no network. See docs/user/compact.md.
- Progressive disclosure (opt-in): with `hooks.disclosure: progressive` the prompt hook injects the first two results as full blocks (the first excerpt whole within the usual budget, the second at most 300 characters; title line `Title (path#anchor)`) and the next up to six as one-line pointers `- Title › Heading (path#anchor)` under `More matches (open with wiki_read_page path + anchor):`; pointer pages are not marked as shown. `wiki_read_page` accepts `anchor` (or `path#anchor`) to return one section with its heading path, and `maxChars`; `wiki_query` accepts `compact: true` to omit snippets. Without the new options every output is byte-identical (745/745 hook outputs on dev and holdout sets). Measured: injected characters 0.42x (dev) and 0.51x (holdout) with the needed page still injected (Δ −0.007 / 0); on long pages the cost of reaching the right section did not improve (1.06x / 0.90x, target was 0.4x), so the mode stays off by default. Tuned afterwards (first block whole, second 300 characters, chosen on dev sets only): on the holdout injected characters 0.48x and the cost of reaching the right long-page section 0.87x; in a blind agent-level test with one optional section read, answer accuracy was 0.576 versus 0.593 with the full format at 0.64x the characters. Still off by default.
- Usage measurement (opt-in, content-free): new command `brainatlas usage [--days N] [--json]` summarises the hook metrics of the last N days (prompts, outcomes, injection rate, mean results and characters, p50/p95 duration, shadow comparison, feedback counts) and `brainatlas usage feedback useful|not-useful` records a one-word verdict in `metrics/feedback.jsonl` (0600, symlinks refused). New optional `retrieval.shadow.abstainThreshold`: the prompt hook also computes how a different relevance threshold would change the result and adds only `shadow: {top1Same, overlap5, injectDiff}` to the metric line; what the agent sees is byte-identical (275/275 outputs on five evaluation sets) and hook p95 is unchanged within ±1 ms, because the threshold only decides whether a result is returned, so a second search runs only when the outcome could differ. Without the setting, output and metric records are identical to before. See docs/user/usage.md.
- Page names with Turkish or accented letters: `wiki_create_entity` and `wiki_create_concept` now transliterate them for the file name (`ç ğ ı İ ö ş ü` to `c g i i o s u`, then Unicode NFKD with combining marks removed), so `Deneme Varlık` becomes `entities/deneme-varlik.md` instead of `deneme-varl-k.md`, names such as `Çağrı Merkezi` and `Ağrı Merkezi` no longer collide, and names made only of Turkish letters are created instead of refused. Existing pages keep their paths. A name with no letter or digit left after transliteration (for example only CJK characters or emoji) is still refused with `E_INVALID_INPUT`.
- Semantic search in the prompt hook (Full, opt-in): when `semantic.enabled` is true, the profile is not Lite and the semantic module is installed, the per-prompt hook runs the same hybrid search as `wiki_query` within a 350 ms sub-budget; on timeout, provider error, missing index, fingerprint mismatch or a non-loopback URL it falls back silently to the keyword result for the same prompt. The semantic module is loaded only by dynamic import and never in Lite. The metric line gains a content-free `semantic` field (`used` or `fallback:<reason>`). On an independent synthetic cross-language holdout with the real local model, Turkish questions about English pages got the right page injected in 8/10 cases (0/10 before); hook p95 about 240 ms; false injections on unanswerable prompts unchanged (0.8). See docs/user/semantic.md.
- Provenance trust in ranking: a page with `status: confirmed` and at least one valid `verified` record (real calendar date, evidence, scope, source) ranks 1.5x higher, `proposed`/`disputed` pages 0.9x, everything else unchanged; abstention is decided before this weighting, and linked neighbours carry their own factor. Results show an optional `trust` field and the prompt hook marks weak pages `[unverified]`. On an independent synthetic holdout where a misleading unverified page matched the query words three times better, the verified page came first in 16/16 cases (0/16 before). Vaults without OKF fields are unaffected. Existing caches are rebuilt once.
- New command `brainatlas maintain [--json] [--vault PATH] [--queue]`: a read-only maintenance report (expired `stale_after`, broken `superseded_by`, broken links, orphan pages, pages missing from or stale in the index, oversized pages, pages with many dated update sections). It never writes; `--queue` adds review proposals to the receipts queue when that module is installed. See docs/user/maintain.md.
- MCP index edge cases (bug fixes): page names with control characters use `<…>` link targets, index labels drop control and line-break characters, a name that produces an empty file name is refused, `wiki_create_entity/concept` write the content's frontmatter and the same index line as `wiki_update_index`, and one unreadable page no longer fails the whole index update.
- Linked pages: retrieval now builds a graph from `[[wikilinks]]` (including `|label` and `#section` forms, resolved by title, alias or file name) and relative Markdown links, and adds direct neighbours of the top three results with half of their source score, so a page that holds the second half of an answer but none of the query words can now be returned. The first result and abstention are unchanged, and unlinked vaults return identical results. Results can carry an optional `related` list and `via: "link"`. On an independent synthetic holdout of two-page questions, the rate of returning every needed page in the top five rose from 0/20 to 17/20. Existing caches are rebuilt once.
- MCP index writes (bug fixes): `wiki_create_entity`, `wiki_create_concept` and the first `wiki_update_index` without an index file now use the same minimal, escaping writer (hand-written index lines are kept); `wiki_status` computes index coverage with the same parser; links with `#anchor` or `?query` count as linking the page; file names with spaces use `<…>` link targets, and names containing line breaks are left out of the index.
- Current-state answers: when a result page has several matching sections, the snippet now comes from the newest valid dated section (`## Update 2026-03-04 …`, `## Current state …`, ISO or `DD.MM.YYYY` dates; future dates ignored) instead of the section with the most matching words, so "what is the current state" questions stop surfacing outdated sections. Ranking, scores and abstention are unchanged. On an independent synthetic holdout the correct-section rate rose from 6/15 to 13/15. A result that replaces superseded pages now lists them in an optional `supersedes` field. Existing caches are rebuilt once.
- Retrieval (bug fixes): snippets shortened to a character budget (for example by `wiki_query`) never split an emoji or other astral character; file-name suffixes of very deep paths (13+ components, including hyphenated names) are indexed by path component, so a path that exists in the vault no longer abstains with `identifier-not-found`. Measured cost on an extreme synthetic vault where every one of 2,000 pages mentions a 20-component path: cache 3.8 → 5.5 MB, warm load about +23 ms; no change on ordinary vaults. Existing caches are rebuilt once.
- MCP write tools (bug fixes): `wiki_update_index` no longer rewrites a curated index from scratch, which erased hand-written summaries, notes and ordering; it now only adds missing pages and removes entries for deleted pages, leaving every other line untouched (code fences included), escapes parentheses in link targets, and never indexes symlinked pages or directories. When `wiki/` resolves outside the vault, tools refuse (`E_PATH_ESCAPE`) or show an empty Wiki instead of exposing outside files. `wiki_update_page` rejects unknown `patch` fields (including `__proto__`) instead of silently ignoring them, and applies `body` and `append` together in order.
- Identifier-aware retrieval: code-like identifiers (snake_case and error codes, CamelCase, versions such as `2.4.0-rc.12`, file names and paths, `--flags`) are indexed whole, so an exact match ranks first, and a short query about an identifier that appears nowhere in the vault now abstains (`reason: identifier-not-found`) instead of returning pages that only share its parts. Dates (for example `11.11.2025`) and abbreviations such as `i.e.` are not treated as identifiers. Queries without identifiers return exactly the same results as before. On an independent synthetic holdout set, correct abstention for unknown identifiers rose from 1/12 to 11/12 and first-result accuracy from 10/12 to 11/12. Known limits: an identifier is matched whole (no Turkish suffix without an apostrophe, no non-contiguous path pieces). Existing caches are rebuilt once.
- Retrieval freshness and speed: the MCP server now notices pages changed outside it (Obsidian edits, sync, another agent's MCP process) on the next `wiki_query`; before, its keyword index only refreshed after its own writes. The index cache key is a file-metadata fingerprint (no page reads when nothing changed), the cache uses a compact layout with strict structural validation (a malformed or inconsistent cache is rebuilt), and the semantic path reuses the in-memory keyword index instead of rebuilding it per query. Measured on a synthetic 2,000-page vault on one Mac: prompt hook p50 about 327 → 133 ms, semantic query path p50 about 266 → 15 ms; rankings and scores unchanged. Existing caches are rebuilt once. The cache lives only in the state directory and is trusted as user-owned data (see `docs/contracts/retrieval.md`).
- Prompt hook (security and correctness fix): snippets are now redacted before they are shortened, closing a case where a truncated fragment of a secret-like value could reach the agent context; each injected block keeps its complete `Title (path)` line (no partial titles at small budgets) and is never title-only; only pages that were actually injected are remembered as already shown in the session; the retrieval call no longer applies a cumulative snippet budget. Output limits per client and mode are unchanged.
- Session start (Claude Code, Copilot, Gemini): when no `handoff.md` exists, the hook now injects a short, deterministic recap card built from the last 14 days of machine entries in `wiki/log.md` (up to 5 recently changed pages with dates and titles) and, when the receipts module has a queue, the number of pending review candidates. At most 800 characters, redacted, no new configuration, not produced in `manual` mode. The recap code loads only on session start; the per-prompt hook path is unchanged (measured +0.3 ms p50). In a small synthetic "where did we leave off" evaluation with a blind scorer, agents with the card named the active topics correctly in 10/10 scenarios versus 0.55 average without it.
- Repository evaluation tools (not shipped in releases): `eval/hook-eval.mjs`, `eval/scale-bench.mjs`, `eval/gate.mjs`, `eval/ba-suite.mjs` and new development sets for identifiers, current-state questions, multi-hop questions and near-topic negatives (see `eval/README-ba.md`).

## 0.1.0-rc.10 — 2026-11-09

Reliability of semantic indexing on slow machines. Indexing is not faster: on a 2012 CPU it stays about 1.2 seconds per chunk (about 16 minutes for 819 chunks). What changes is that it completes with default settings, keeps its progress, and tells you how long it will take. Fast machines behave as before (the index written is byte-identical for the same provider).

- Indexing has its own settings: `semantic.indexTimeoutMs` (per request, default 120000) and `semantic.indexBatchSize` (texts per request, 1–64, default 32). The query timeout `semantic.timeoutMs` (default 5000) is unchanged. Before this, a slow host failed `semanticSetup` at the first batch because the query timeout also applied to indexing.
- Adaptive batches: a batch slower than 20 seconds halves the next batch, a batch faster than 5 seconds doubles it (up to `indexBatchSize`).
- Resumable indexing: progress is saved to `index.partial.json` in the state directory at least every 30 seconds and on error or cancel; running the command again embeds only the missing chunks, and the final index is identical to a single clean run. `brainatlas semanticStatus` reports `partialChunks`. A process killed with SIGKILL can lose up to 30 seconds of progress. Queries never read the partial file.
- Progress and estimate: `semanticSetup` shows one updating progress line with an estimated remaining time instead of one line per file. If the estimate exceeds 5 minutes it says so and, in an interactive terminal without `--yes`, asks once before continuing (declining keeps the saved progress). `--dry-run` reports how many chunks are still to embed.
- A lock file prevents two indexing runs at the same time (`E_SEMANTIC_BUSY`); `semanticSetup` reports "Another indexing operation is running."
- The MCP server's background index refresh now uses the indexing settings (it previously used the query timeout) and is cancelled when the server closes (it waits at most 2 seconds).
- Not re-measured on the 8 GB reference host after these changes; verified with a real Ollama behind a delayed proxy (default settings, kill and resume).

## 0.1.0-rc.9 — 2026-11-09

- New guided command `brainatlas semanticSetup` for the optional semantic retrieval. It checks that Ollama is installed and running, offers the ~240 MB embedding model download, builds the local index, verifies it with a probe query, and enables `semantic.enabled` only after everything succeeded. It never installs Ollama (it prints the official install command instead), never uses `sudo` or `curl | sh`, and only talks to the configured loopback address. `--dry-run` changes nothing; without a terminal and without `--yes` it behaves like `--dry-run`; `--mode semantic-primary|rrf` selects the retrieval mode. Exit code 0 when ready, 2 when an action is still needed.
- `brainatlas doctor` no longer warns "Semantic index is not available." while semantic retrieval is off; the `semantic` health entry now includes `enabled`.
- Install guide: GitHub Release assets cannot carry the `release/` subdirectory, so the guide now points to the `brainatlas-<version>-distribution.tar.gz` asset; troubleshooting covers missing Ollama, a stopped server, a missing model and a stale index.

- Secret filter: Markdown page titles containing "secret" are no longer refused on their own; `brainatlas safety allow|list|revoke` records fingerprinted exceptions for reviewed false positives (new or changed matches are still refused).
- Releases are published on GitHub Releases.
- Agent MCP/hook launch: `bin/brainatlas` runs under both sh and node (MCP connections were closing on start).
- Claude Code and Gemini hooks use the CLI hook contract (`hook <client> <event>`); legacy entries are upgraded on install.

## 0.1.0-rc.6 — 2026-11-08

- `brainatlas sync schedule install|remove|status` installs a LaunchAgent (macOS, label `org.brainatlas.sync`) or a systemd user timer (Linux); safe temp files, HOME containment, failed stops keep files and can be retried; `uninstall` removes the schedule.
- A never-synced host's untouched init-template files yield to remote content on first sync (no seed conflicts).
- Tests no longer inherit `BRAINATLAS_OFFLINE` from the environment.

## 0.1.0-rc.5 — 2026-11-08

- Codex adapter parses real-world `config.toml` (quoted table headers, inline tables, multi-line arrays and strings, array tables); markers inside strings are ignored; an agent config directory that resolves outside HOME is refused unless `BRAINATLAS_ALLOW_SYMLINKED_ROOT=1`.

## 0.1.0-rc.4 — 2026-11-08

- `init` preserves an existing configuration (vault path from `install.sh --vault`, sync settings, host id); only flags given explicitly change it.

## 0.1.0-rc.3 — 2026-11-08 (built and verified locally, not tagged: `init` reset an existing configuration)

- `init` now creates the vault skeleton (idempotent, never overwrites); `migrate` accepts a destination that only holds an untouched init skeleton.
- `--json` commands print exactly one JSON value on stdout; errors use `{"ok":false,"error":{…}}`; module logs go to stderr.
- Removed build artifacts accidentally committed under `release/dist/`.

## 0.1.0-rc.1 — 2026-11-08 (local release candidate; signed with a development key, not published)

- Added Lite and Full release profiles with signed archive verification and install/update/rollback support.
- Added local configuration, vault paths, doctor/status checks, and managed uninstall behavior.
- Added coding-agent adapters for Claude Code, GitHub Copilot in VS Code, Kiro, Codex CLI, and Gemini CLI.
- Added MCP tools for Wiki retrieval, reading, status, lint, and controlled writes.
- Added bounded hooks, local secret filtering, path deny rules, and privacy-preserving hook metrics.
- Added OKF v0.2-inspired local metadata checks and optional strict module.
- Added optional Git and Dropbox synchronization modules; folder sync is experimental.
- Added optional semantic retrieval behind an evaluation gate; experimental and off by default.
- Added `migrate` (copy-based, source read-only), `adopt --plan` and `help`.
- Added session-end receipts with a human review queue (Full).
